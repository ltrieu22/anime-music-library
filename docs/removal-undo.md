# Undo song removals

Roadmap item 10 adds Undo to Saved Songs heart controls (including the player), playlist row removals, membership removals in Add to playlist, single/bulk playlist deletion, and queue removals/Clear upcoming. Existing removal confirmations remain.

- The latest removal offers **Undo** for 5 seconds. Another removal replaces that offer. Hover or keyboard focus pauses expiry; leaving provides another 5 seconds. Dismiss ends the offer. Buttons show a pointer cursor and hover color feedback. Offers are session-only and disappear on reload, import, or collection reset.
- The picker displays the action inside its modal, keeping it reachable by keyboard. Queue Undo appears in a small floating window beside the queue on wide screens and above the player on narrow screens; it never takes space in the queue layout. Closing either retains the action on the page. Activating Undo or Dismiss returns focus to the dialog, queue or collection/search controls.
- Undo restores the exact saved entry or playlist reference, including manual IDs and snapshots. It reads current storage, inserts before the nearest surviving following neighbor (otherwise after a preceding neighbor), and preserves unrelated edits. Without surviving neighbors it uses the original position, bounded by the current length.
- Playlist membership Undo changes only the original playlist membership. Whole-playlist Undo restores original IDs, names, snapshots, memberships and library order; bulk restore is atomic. Saved Songs Undo changes only Saved Songs. These operations preserve notes, other lists, current media, and queue occurrences.
- Failed library removal leaves storage/UI intact and creates no new offer. Failed Undo retains **Retry Undo** without expiry. Repeated restoration does not duplicate membership. A reused saved number or an independently re-saved song produces an explicit conflict rather than overwriting or duplicating data.
- Queue Undo restores exact occurrence IDs into the upcoming queue without changing current media, time, play/pause state or repeat mode. Undoing current-song removal puts that song next while its successor keeps playing. If removal closed the player, Undo restores its retained queue paused at the removed song's position. Closing or replacing the queue invalidates the older queue Undo. Queue restore saves before updating the UI and offers Retry Undo on failure; ordinary queue edits retain the existing playback-storage error/retry behavior.
- Whole-playlist restore never overwrites reused IDs or conflicting names: it reports the conflict and keeps Retry Undo available. Song-membership Undo never recreates a deleted playlist.

Verification: service tests cover identity, order, unrelated edits, storage corruption/failure/retry, duplicate and ID/name conflicts, atomic bulk restoration, queue occurrence IDs and current-media preservation. `node tests/removal-undo.mjs` exercises the production UI with isolated storage, blocked external requests, local WAV playback and a controlled clock: single/bulk playlist deletion, queue/current/clear removal, paused tail restoration, cancellation, failure/retry, keyboard activation, pointer cursors, focus pause, five-second expiry, persistence, notes and uninterrupted media. Desktop page and floating queue notifications were visually reviewed.
